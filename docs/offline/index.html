DroidBox Documentation

DroidBox is a lightweight, free, open-source Android application testing environment designed specifically for Windows developers. It lets you run, test, and debug Android APKs directly on Windows without requiring a physical device.

Core Principles

  • 100% Free and Open Source (Apache 2.0 License).
  • No advertisements, telemetry, or mandatory user accounts.
  • No background bloatware or persistent telemetry daemons.
  • Native Windows WPF desktop UI and developer-first CLI.
  • WHPX hardware acceleration for fast, smooth virtualization.

Getting Started

To verify that your Windows machine has all required virtualization and SDK dependencies installed, run the DroidBox Doctor command:

droidbox doctor

Doctor checks your Windows Hypervisor Platform (WHPX), ADB binary, Android SDK tools, and emulator installations. If components are missing, run the automated provisioner:

.\scripts\setup-runtime.ps1

CLI Reference

DroidBox includes a standalone, command-line tool (droidbox.exe) designed for terminal power users, automation pipelines, and CI/CD agents:

  • droidbox doctor - Diagnose environment, virtualization, and SDK status.
  • droidbox devices - List all pre-configured virtual device profiles (tablet, mobile).
  • droidbox install <path-to-apk> - Install and verify an APK.
  • droidbox apps - List all installed Android applications.
  • droidbox launch <package-name> - Launch an app in the running emulator.
  • droidbox uninstall <package-name> - Uninstall an application.
  • droidbox screenshot [--output <path>] - Capture an emulator screenshot.
  • droidbox stop - Safely shut down running emulator instances.

Desktop Application

The DroidBox Desktop GUI provides an intuitive native Windows interface with:

  • Dashboard: Real-time emulator status, device profile selector, and recently installed applications.
  • APK Manager: Drag-and-drop installation for .apk packages, package inspection, and one-click uninstallation.
  • Virtual Screen: Live streaming display with mouse and touch input forwarding.
  • Settings: Dark/Light theme switching and SDK storage configuration.

Flutter & React Native Integration

Because DroidBox runs the official Android ADB daemon on standard ADB ports (5554/5555), standard mobile development tools automatically detect it as an active Android device:

# Flutter
flutter devices
flutter run

# React Native
npx react-native run-android

Python SDK Automation

Automate end-to-end tests using the bundled Python SDK in samples/python/droidbox.py:

from droidbox import DroidBox

client = DroidBox()
client.doctor()
client.install("path/to/my-app.apk")
client.launch("com.example.myapp")
client.screenshot("test-result.png")

Troubleshooting

Hardware Acceleration (WHPX)

Ensure Windows Hypervisor Platform is enabled in Windows Features:

Enable-WindowsOptionalFeature -Online -FeatureName HypervisorPlatform

ADB Port Conflicts

If ADB fails to connect, restart the ADB daemon:

adb kill-server
adb start-server
